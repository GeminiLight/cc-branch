Why it exists

A project is no longer one terminal.

Agent sessions scatter

Codex, Claude, Gemini, review panes, and long-running terminals all need a stable place to return to.

Context lives in terminals

Dev servers, logs, shell state, and editor launch commands are part of the workspace, not afterthoughts.

Remote machines matter

Some panes belong on SSH hosts. CC Branch treats them as first-class workspace targets.

The model

One local contract for the whole workspace.

Keep the workspace contract in `.cc-branch/config.yaml`. Runtime state stays local, so teams can share the shape without sharing machine-specific sessions.

.cc-branch/config.yaml 
workspace: orbit
openWith: cursor
tabs:
  - name: agents
    layoutBackend: tmux
    panes:
      - agent: codex
        resume: planner
      - agent: claude
        label: review
  - name: remote-lab
    ssh:
      host: gpu-dev
      cwd: /srv/orbit
    panes:
      - command: npm run qa
01 define

Describe tabs, panes, agents, commands, openers, and SSH targets.

02 preview

Run `cc-branch plan` to see what will start, attach, or open.

03 restore

Bring the whole workspace back with `cc-branch start`.

04 inspect

Use doctor checks to catch missing tools, bad paths, and state drift.

Remote workspaces

Local project. Remote machine. Same workspace.

Add projects and panes that live on SSH hosts, then launch them beside local agents and servers. The directory can be local or remote; the workspace still opens as one unit.

local ~/code/orbit cursor
ssh gpu-dev:/srv/orbit tmux

Desktop shell

A quiet desktop shell for local work.

The desktop app wraps the Web UI with a local sidecar, so switching projects, checking status, and restoring sessions feels like a native utility.
